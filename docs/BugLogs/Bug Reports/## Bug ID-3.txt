## Bug ID
BUG-003

### Date
2026-07-24

### Version
Unknown

### Category
Infrastructure / Spring Boot / Neo4j Connectivity

### Severity
Medium

### Status
Resolved

### Detection Method
Runtime Exception (HTTP 500 Internal Server Error)

### Symptoms
All backend operations requiring Neo4j failed with an HTTP 500 response.

Error message:

```text
Could not open a new Neo4j session:

Unsupported authentication token,
scheme 'none' is only allowed when auth is disabled:
{ scheme='none' }
```

### Immediate Cause
Spring Boot failed to establish a new session with the Neo4j database because the Neo4j driver attempted to use an unsupported authentication token.

### Root Cause
This was a transient infrastructure issue rather than an application code defect.

The Spring Boot application and/or Neo4j connection state became inconsistent, causing the Neo4j driver to fail when creating new sessions. Restarting the server reinitialized the Neo4j driver and restored normal connectivity.

### Investigation Summary
- Verified the error originated during Neo4j session creation.
- Initially suspected Neo4j authentication configuration.
- Reviewed recent application changes and confirmed no authentication-related code modifications.
- Restarted the Spring Boot server.
- Neo4j connection was successfully re-established.
- All API endpoints resumed normal operation without any code changes.

### Fix Implemented
No code changes were required.

Resolution:

1. Stopped the Spring Boot application.
2. Restarted the backend server.
3. Verified successful Neo4j connection initialization.

### Files Changed
None.

### Verification
Confirmed:

- Application starts successfully.
- Neo4j session creation succeeds.
- Product APIs function normally.
- No further authentication token errors observed.
- Database connectivity fully restored.

### Regression Risk
Very Low

The issue was caused by a transient runtime state rather than application logic.

### Prevention
- If Neo4j session/authentication errors suddenly appear without configuration changes, restart the Spring Boot application before investigating code changes.
- Verify Neo4j Desktop/server is running before starting the backend.
- If the issue becomes recurring, investigate:
  - Neo4j server availability
  - Driver version compatibility
  - Environment variable loading
  - Connection pool configuration

### Lessons Learned
Not every HTTP 500 originates from application code. Infrastructure components such as database connections or driver state can occasionally enter an inconsistent runtime state, and a clean application restart can restore normal operation before deeper debugging is required.
