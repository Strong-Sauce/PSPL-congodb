# Product Warranty Foundation

**Status:** ✅ Completed (Core MVP)

---

# Feature Overview

The Product Warranty Foundation establishes a backend-driven workflow for automatic warranty creation. Every product now belongs to a Product Category, which serves as the single source of truth for category-specific business rules such as serial number generation and default warranty duration.

This implementation removes manual warranty creation from the user workflow and ensures that critical business fields are generated and controlled exclusively by the backend.

---

# Objectives

Completed objectives:

- Introduce Product Categories.
- Automatically generate business-friendly Product Serial Numbers.
- Automatically create an initial Warranty during Product creation.
- Centralize category-specific business rules.
- Prevent clients from manipulating backend-managed fields.
- Build a scalable foundation for future Warranty renewals and AMC features.

---

# Architecture Decisions

## Product Category as the Source of Truth

Instead of storing warranty information independently, the Product Category now owns category-specific metadata.

Each category contains:

- Display Name
- Serial Prefix
- Default Warranty Duration (months)

Example:

| Category | Prefix | Warranty |
|----------|--------|----------|
| LAPTOP | LAP | 24 Months |
| SERVER | SRV | 36 Months |
| ROUTER | RTR | 12 Months |

This keeps business rules centralized and eliminates duplicated configuration throughout the application.

---

## Product Serial Numbers

The internal Neo4j identifier remains an implementation detail.

Users now interact exclusively with a generated Product Serial Number.

Example:

```
LAP-7F4A91
RTR-91AF2C
SRV-AB9821
```

Generation strategy:

- Category Prefix
- Random UUID fragment
- Retry until unique

Benefits:

- Human-readable
- Search-friendly
- Unique
- Independent of database implementation

---

## Automatic Warranty Creation

Warranty creation is now entirely backend-managed.

Workflow:

```
Receive Product
        ↓
Validate Request
        ↓
Assign Creation Date
        ↓
Generate Serial Number
        ↓
Generate Initial Warranty
        ↓
Attach Warranty
        ↓
Persist Product
```

The user never manually creates or associates the initial warranty.

# Business Rules

Implemented rules:

- Every Product belongs to exactly one Product Category.
- Product Category determines:
  - Serial Number Prefix
  - Default Warranty Duration
- Product Serial Number is generated automatically.
- Product Creation Date is generated automatically.
- Initial Warranty is generated automatically.
- Warranty is attached automatically during Product creation.
- Users cannot manually enter Product Serial Numbers.
- Users cannot manually create the initial Warranty.
- Backend ignores client-supplied values for backend-managed fields.
